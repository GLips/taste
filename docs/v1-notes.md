# Taste v1: build notes

Deviations, shortcuts and open questions, recorded by each build stage.

## Stage 1: foundation (scaffold + src/core + tests)

- **SQLite:** core wraps `bun:sqlite` directly instead of `@effect/sql-sqlite-bun` (installed, unused). The index is a disposable cache refreshed with sync prepared statements; the Effect SQL client added async plumbing for no gain. Effect services/errors still wrap it.
- **Filesystem:** core uses `node:fs` sync calls inside Effects rather than an Effect `FileSystem` service (no platform package needed).
- **Runtime:** core needs Bun (`bun:sqlite`). `dev:review` is `bun --bun vite --port 4747` so server functions run under Bun; plain `vite` under Node would fail to load core.
- **Index tables:** one `records` table (with `type` and a `ref` column holding a decision's target or a thread entry's belief) plus `files` and an FTS5 `search` table, instead of separate decisions/threads tables. Status and reverse links are computed in TypeScript from a full snapshot on every read; fine at demo scale.
- **Freshness:** any removed or touched file triggers a full rebuild; new files are added incrementally. `rebuildStoreIndex` deletes only `taste.sqlite*`, so listener cursors in `.index/listeners/` survive `taste reindex` (deleting `.index/` by hand resets them).
- **UUIDv7:** generated in core, not `Bun.randomUUIDv7()`, whose `rand_a` is a sub-ms counter (ids looked like `…-7000-…`). The short id skips the version nibble (`hex[13..21]`) since it is always `7`; widened in steps of 2 on collision.
- **Decision `via`:** added an optional `via` field (e.g. `process:seed`) so the seed can record it wrote on `human:demo`'s behalf. `by` is always the store owner, so the seed store should be initialised with `owner: human:demo`.
- **Thread authors:** a `human:` author must equal the store owner; anything else is treated as an agent actor. The CLI should still refuse `--as human:*`.
- **Repeat check:** naming any one near match with `--despite` lets a proposal through even if it has other near matches (they're returned as related). The belief named in `supersedes` is excluded from the repeat check, otherwise every revision would be refused as a repeat of what it revises.
- **Stopwords include negations** (`not`, `never`, `only`, `always`, `don't` fragments), so "Use X" and "Never use X" are near repeats. Deliberate (a human should see both), but it's a product call. Open question.
- **Recall:** FTS5 (porter stemming, prefix match on each normalised token, OR-joined), ranked by bm25. `limit` defaults to 5 per section. Superseded/retracted matches go in a separate `history` section (only with `history: true`) rather than being mixed into Believed. Pending beliefs never appear in recall.
- **Hook payload:** at most 3 items total, believed before not-believed, no quotes (spec says never raw memories). `buildHookPayload` returns `hookOutput` (the exact stdout JSON) or undefined for "print nothing". Scope (`appliesTo`) is optional; how the hook derives a scope (cwd basename?) is for the hook stage.
- **Listener:** emits human thread entries only; it does not emit decision events (spec says "polls threads (and decisions)"; the line shape has no slot for decisions). Open question. The first poll ever only creates the cursor, so history before the listener started is never printed.
- **Times:** `said_at` may omit seconds (minute precision is inferred); all times need an offset (`Z` accepted). New records are stamped in local time with ms and offset.
- **Body parsing:** memory body sections split on `## Quote|Before|After` lines; a quote containing such a line would be split there.
- **Added for the UI stage:** `listInboxGroups` (pending beliefs grouped by subject then sorted `applies_to`, each card with related beliefs) and `listListenerHeartbeats`.
- **Typecheck:** `tsc` 7.0.2 (TypeScript 7 native) with `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`. `tsconfig.json` already includes `hooks/` and `vite.config.ts` for later stages.

## Stage 2: CLI, listen, seed, hook, skill

- **effect/cli platform:** `@effect/platform-bun` isn't installed, and `Command.run` needs FileSystem, Path, Terminal, ChildProcessSpawner and Stdio. `src/cli/runtime.ts` builds a minimal layer by hand: noop FileSystem, posix Path, Stdio args from `process.argv`, and a Terminal/spawner that die if used. Taste uses no prompts, file flags or effect child processes.
- **Global flags:** `--json` and `--store` are declared on every leaf command rather than as effect/cli global flags. They must come after the subcommand (`taste recall x --json`).
- **Exit codes:** 1 is used for unexpected failures (corrupt file, write failure, lock timeout, defects); the spec only defines 0, 2 and 3. effect/cli parse errors (missing flag, unknown subcommand) exit 2. A store that is missing or already exists exits 2.
- **Errors under `--json`:** printed as `{"error": {...tagged error...}}` on stdout, so a `--json` caller always gets JSON; text-mode errors go to stderr.
- **Ids in output:** text output prints full UUIDs (unambiguous, copy-pasteable). Short ids are only in file names; refs accept either.
- **capture:** with `--json` and no `--quote`, the input is a capture object on stdin, and `--via` fills `captured_via` if the JSON omits it. Otherwise `--said-by --label --quote --via` are required (checked by the CLI, which names the missing flags). `--said-at` defaults to now (local, second precision). Added flags the spec's list omits: `--revises` and `--precision`.
- **propose:** reasoning comes from `--reason`, else all of stdin. Agent shells give `/dev/null`, so stdin is safe there; an inherited pipe that never closes would block. Added `--subject` and `--contradicts`.
- **init:** `--owner` defaults to `human:$USER`.
- **seed:** creates the store with `owner: human:demo` if none exists. It refuses (exit 2) when the store has records, or when its owner isn't `human:demo` (decisions are always `by` the owner). Every seed actor (`captured_via`, `proposed_by`, the agent thread reply, decision `via`) is `process:seed`, so the fiction is labelled as such. All records go through core, so the repeat check and status rules apply to the seed too. Records are stamped at seed time; only `said_at` is in the past.
- **review:** spawns `bunx --bun vite --port <port> --strictPort` from the repo root with `TASTE_STORE` set to the absolute store root. `--bun` is a deviation from the plain `bunx vite`, because core needs `bun:sqlite`. It checks the store opens before starting.
- **listen:** prints a "listening as … on …" line to stderr, so stdout carries only JSON lines. Heartbeat and poll run as two fibers sharing core's cursor helpers. `--json` is accepted and has no effect.
- **thread reply:** refuses `--as human:*` (exit 2), on top of core's owner check.
- **Core change (store-files.ts):** `writeFileExclusive` now writes a temp file and hard-links it into place (`link` fails if the target exists, so it's still exclusive). Before, a 500ms poller (listen, the UI) could read the empty file between `open` and `write` and fail with CorruptRecordFile.
- **Core change (similarity.ts):** `use/uses/used/using` are now stopwords. Without that, any prompt containing "use" matched every "Use …" belief, so the hook injected unrelated rejections ("should I use a default export" pulled in "Use Tailwind everywhere"). Core tests still pass. Open question: other imperative filler words ("prefer", "avoid") are kept because they carry stance.
- **Hook scope:** the hook reads `TASTE_SCOPE` for `applies_to`; when it's unset, every scope is eligible and each item is labelled with its scope. Deriving the scope from the cwd basename was rejected for now: a project directory name that differs from the scope label would silently hide every scoped belief. Product call. `taste hook preview` defaults `--applies-to` to `TASTE_SCOPE` too, so it matches the hook.
- **Hook deadline:** the 650ms timer starts when the script starts, after Bun's startup (about 100ms). Measured: about 150ms end to end with a warm or a missing index. A stdin that stays open past the deadline makes it exit 0 with no output after about 760ms wall time. A missing store prints nothing and exits 0. Other failures exit 1 (non-blocking in Claude Code) with a stack on stderr.
- **Hook preview output:** text mode prints the `additionalContext` text (what the model sees). `--json` prints the whole payload, including `hookOutput`, the exact stdout bytes.
- **Not done:** no CLI-level automated tests (core's 5 tests cover the behaviour; the CLI was verified by hand, see the stage report). `--json` isn't a global flag, so `taste --json recall …` is a parse error.

## Stage 2: review UI (vite config, src/server, src/routes, src/ui)

- **Server function file naming:** the `createServerFn` references live in `src/server/review-functions.ts` (plain `.ts`), and core is reached only through `src/server/taste-store.server.ts`. The spec says `*.server.ts` for server functions, but importProtection denies every `*.server.*` file to the browser, and the browser must import the function references. This is the tk2/media-studio convention: a file exporting `createServerFn()` gets a plain name.
- **importProtection:** the client may not import `**/*.server.*`, `**/src/core/**`, `bun:sqlite` or `node:*`. Checked with a throwaway route that imported a value from core: Vite refused it ("Import denied in client environment"). Type-only `import type` from core in UI files is erased before resolution, and the UI uses it for record and view types.
- **Store path:** `TASTE_STORE` is read on every request via `resolveStoreRoot` (falls back to `./.taste`). Every server function opens the store and closes it again; inbox and detail calls measured 11 to 15ms.
- **Decision results:** `decideReviewBelief` and `acceptReviewGroup` return `{ok:false, message}` for every core failure instead of throwing, so the card can show the message inline. Other server functions throw an Error whose message is readable (`describeTasteFailure`).
- **Stale decisions vanish quickly:** the inbox polls every 1s, so a card someone else decided usually disappears before it can be clicked. When the click wins the race, the inline error shows (checked by freezing polls), but it disappears along with the card on the next poll. A toast that outlives the card may be better. Open question.
- **Accept all:** cards are accepted one by one in display order. A failure (say, a second revision of an already retired belief) is listed under the group header and the rest still land. There is no confirmation step; it accepts "Everywhere" beliefs too, so you may want a confirm when a group is unscoped. Product call.
- **Retract** is on the belief page (accepted beliefs only). Accept and reject also live there for pending beliefs.
- **Keyboard:** j/k are registered by the inbox. a/r/d are registered by a component mounted only inside the selected card, so they always act on exactly one card. With nothing explicitly selected, the first card is selected. When a decided card vanishes, selection falls to the card that took its place. In the reject field, Cmd/Ctrl+Enter submits and Esc cancels.
- **Related beliefs** on a card show "N% similar" only at 0.35 or above. Below that they're top FTS hits, labelled "shares wording" instead of a misleading "0% similar".
- **Supersede chain:** the detail server function walks `supersedes` back to the oldest ancestor (capped at 50 hops) and appends `revisions` (any status). The chain is shown oldest first.
- **Recall inspector:** recall uses core's default limit (5 per section). The hook payload uses `buildHookPayload` (limit 3) with the same prompt and scope, so the hook's believed items are always a subset of the recall shown. Provenance for believed items shows their cited quotes. For not-believed items it shows the rejection date and reason. The raw hook stdout JSON sits in its own expander.
- **Styling:** light scheme only, Mantine `indigo` primary, StyleX for layout and a few accents (selected card, despite panel, quote rule). There's no postcss config in media-studio; I added `postcss.config.cjs` with `postcss-preset-mantine` and the breakpoint vars, per Mantine's docs.
- **Router links:** `src/ui/router-links.tsx` wraps Mantine `Anchor`/`Button` with `createLink`, because `component={Link}` loses the router's typed `to`/`params`.
- **Not done:** no production `vite build` was tried; `taste review` runs the dev server. The first page load after the server starts takes a couple of seconds while Vite transforms modules.

## Stage 3: integration

- **Defect fixed (core, `src/core/store.ts`):** if `.index/` was deleted while `taste review listen` ran, its open SQLite connection hit "disk I/O error" and the listener exited. Every refresh now checks the index file's inode and reopens onto the current file when it has changed or gone. Test 4 now also covers a long-lived scope surviving the deletion.
- **Demo store:** `demo/` is gitignored, and a fresh seed lives at `demo/.taste`. `docs/demo.md` walks steps 1–8.
- **Open question, recall relevance:** project names count as search words. `billing-api` becomes the tokens `billing` and `api`, so the prompt "add tailwind styling to the billing-api admin page" recalls and injects the unrelated accepted "real Postgres" belief. Related lists have the same noise, for example "Use named exports" at similarity 0.00 next to a Tailwind proposal, because the spec counts any top-3 FTS hit as related. Options are dropping scope names from query tokens, or a minimum bm25 score for the hook and for related. I left both alone because the current behaviour is what the spec says.
- **Seed:** the seeded thread's agent entry is authored `process:seed`, not an agent name. That's harmless, but it reads oddly in the UI.
- **Not done:** no production `vite build`. The demo runs on the dev server, as `taste review` does.

## Stage 4: review findings

- **Owner spoofing (fixed):** core now has `appendAgentThreadReply` and `appendOwnerThreadNote` instead of one `appendThreadEntry` that took any author. The agent path trims the name and refuses any `human:` name, so `--as " human:demo"` exits 2 and writes nothing. Only the review UI's server function (and the seed, which owns its store) calls the owner path. Test 5 covers the padded name.
- **TasteStore is a service with methods:** `snapshot`, `search`, `write`, `rebuild`, plus `root` and `config`. The SQLite handle and the reopen-if-deleted check are private to `makeTasteStoreLayer`. `loadStoreSnapshot` and `rebuildStoreIndex` remain as one-line `TasteStore.use` shorthands.
- **`store.search` refreshes the index first,** like `snapshot`. The inbox runs one search per pending card, so it walks the record files N+1 times per poll. That's fine at demo scale; a shared fresh-index handle per request would remove it.
- **`src/shared/`** holds browser-safe vocabulary (`BELIEF_STATUSES`, `DECISION_OUTCOMES` and their Schemas, `shortIdOf`, `formatScopeLabel`) and the input-cleanup Schemas. importProtection already allowed it. The beliefs status filter now lists statuses in tuple order (Retracted before Superseded).
- **One belief projection:** `BeliefSummary` is the base. `RepeatMatch`, `RecalledBelief` and `BeliefView` extend it, while `NearRepeatRefused.matches`, `RecallResult.notBelieved` and `HookPayload.items` hold summaries. JSON shape changes: `notBelieved[].rejectedAt` becomes `decidedAt`, and hook items drop `kind` in favour of `status`. `BeliefView` gained `ancestors`, so the server's supersede walk and its 50-hop cap are gone. A seen-set guards cycles.
- **Beliefs list rows** come from a new core `listBeliefRows` (a summary, plus `replacedBy` and `threadCount`). It replaces `listBeliefViews`. `fetchReviewStoreInfo` uses it for `pendingCount` and `scopes`, so polling no longer runs repeat classification. The recall inspector and the beliefs filter both read their scopes from store-info.
- **Scope naming:** single-value filters are `scope` (`RecallInput`, `RecallResult`, `ListBeliefsFilter`, `buildHookPayload`, `listContextBeliefs`), while `appliesTo` is always the list. The propose input field `why` is now `despite_case`, and the `--why` flag maps onto it.
- **Skipped:** renaming `taste propose --reason` to `--reasoning`. The spec names `--reason` and overrides review findings. The flag still fills the `reasoning` field.
- **Hook text:** an unscoped believed item now reads `Believed (Everywhere)` (it was lowercase), via the shared `formatScopeLabel`.
- **Errors:** errors.ts exports a `TasteError` union. The CLI's exit codes (a `Record<TasteError["_tag"], number>` in cli/runtime.ts) and both message mappers (`Match.valueTags`) are exhaustive, and a defect is reported apart from a typed failure. Exit-code comments are gone from core, and so is `TasteRequestFailed` (the server throws a plain `Error` with the message).
- **Input cleanup:** the input Schemas trim on decode and turn blank or `undefined` optional values into absent keys, and empty lists into absent ones. Operations take the decoded type. The CLI calls `decodeCaptureMemoryInput` / `decodeProposeBeliefInput` at the boundary, and the seed builds decoded values directly. The server decodes `reason` and `scope` with `OptionalTrimmedText`. A blank owner note is refused by the ThreadEntry schema (`InvalidRecordInput`).
- **Removed:** the `records.ref` column and its index, the index layout-version and meta table, `readBeliefThread`, `refreshStoreIndex`, `withDecisionLock`'s export, the `@effect/sql-sqlite-bun` dependency, and most barrel exports. An index built before this stage still works, because inserts name their columns; `taste reindex` gives a clean one.
- **Record files:** frontmatter key order for new memories and beliefs changed slightly, because the decoded input is spread after `id`/`type`/`schema_version`. Content is unchanged.
